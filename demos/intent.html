About this demo — what you're looking at

This is the second fully-cognitive, agent-to-agent case, and a deliberately wider gap than the first. Agent O speaks intent: declarative expectations with quantitative bounds — bandwidth ≥, latency ≤, availability ≥, protection required. Agent N speaks a concrete L1 service: discrete client signals (ODUk), routes, wavelengths, protection schemes. The two differ in nature (a predicate vs a value), in scope (consumer realm vs provider realm), and in abstraction (what to deliver vs how it is delivered). Neither side merges the other's schema; both are competent, interrogable agents that work out the mapping between themselves.

The mapping is a refinement, not an equivalence. An expectation such as bandwidth ≥ 8 Gbit/s does not equal ODU2; it is satisfied by it. So the right test is not that intent → network → intent returns the original bytes — refinement is lossy and under-determined, the provider picks among many valid realizations — but that the chosen realization satisfies every expectation. Verification here is satisfaction, with feasibility / best-achievable / judge when an expectation cannot be fully met.

Two directions, both shown. Refine-down: an intent arrives; Agent N derives and provisions a realization that satisfies it. Assure-up: operational state flows back; Agent O maps it to fulfilment — met, at-risk margin, or breach. Watch the cognition meter (heaviest at planning, the lift, the parametric refinement and the feasibility judge), and the pragmatics — realm (who decides), state (intended vs operational), authority (the judge) — which carry most of this case.

When expectations conflict, the network computes feasibility and returns a best-achievable offer; the intent judge (IG 1253) evaluates it against acceptance criteria and priorities, and accepts a degraded value or rejects. This is the beat where the agents work hardest to nail the answer down — and reach it without a human.

The other direction. Operational state flows up from the network; Agent O maps each measured value to the fulfilment of its expectation — MET, AT-RISK MARGIN, or BREACH. Assurance is verified by the same satisfaction predicate, evaluated on live data.

The negotiated artefact: two directional mappings. Refine-down (intent → L1CSM) is one-to-many — it carries the refinement policy and the provider's choice. Assure-up (operational → fulfilment) is an aggregation to a satisfaction verdict. They are not inverses. Cognition is spent here once; runtime executes with no inference per message.

Same reconciliation, both ways. The reference lexicon does not just save conversation — it saves verification, and it pre-empts the nature false cognate by binding expectations and metrics to different kinds of entry, so "latency ≤ 5ms" is never mistaken for a measured latency.
The form-independent semantic model — meaning (semantics and pragmatics) lifted clear of any form, with provenance. Here the pragmatics carry the case: realm (consumer expectation vs provider realization), state (intended vs operational — the assurance loop), and authority (the feasibility judge). An agent consumes this directly; TMF921 and L1CSM are merely projections of it.
